Time-Weighted Return

Method Is a Choice already set up the question this chapter answers: when the client controls when money moves in and out, that timing has nothing to do with the manager's skill — so a fair performance number has to strip it out entirely. Time-Weighted Return (TWR) is how.

Here's why it matters in dollars, not just in principle. Take a portfolio worth $100,000 that drifts down 10% over a quarter, to $90,000. The client then adds $50,000 — bringing the balance to $149,000 — right before the portfolio drifts down another 10%, closing the next quarter at $134,100. Read the whole period naively, start to finish: $100,000 → $134,100 looks like a spectacular +34.10% gain. But the manager didn't do anything spectacular in either quarter — the portfolio lost 10% both times. The client's own $50,000 contribution, landing right before a decline, is what inflated the ending balance. A manager shouldn't get credit (or blame) for when the client happened to add money.

TWR fixes this by splitting the period at every cash flow and computing a clean return for each piece on its own. For each sub-period: take the value right before that period's own cash flow — the flow itself is new money, not performance — and compare it to the value the prior sub-period ended on, using the same simpleReturn() from the Beginner tier. Chain those sub-period returns together with linkReturns(), exactly the geometric linking Compounding and Geometric Linking already covered. TWR isn't a new kind of math — it's those two ideas applied to a real, multi-point valuation history for the first time.

Run the numbers above through that process and the three quarters read −10%, +10%, −10% — chaining to −10.90%, not +34.10%. That's the manager's actual, client-timing-independent performance. It's also exactly why GIPS, the industry's own performance-reporting standard, requires TWR specifically when the client controls cash-flow timing: a return that moves depending on when someone else added money isn't a fair way to judge, or compare, a manager. (When the fund itself controls timing instead — a closed-end structure, a private equity commitment — that's the opposite case, and it's what Money-Weighted Return, next chapter, is built for.)

Linked (TWR)

  • timeWeightedReturn(entries) splits the period at every cash flow, computes simpleReturn() on each clean sub-period, then chains the results with linkReturns().
  • Each sub-period's return uses the value right before that period's own cash flow — the flow itself is new money, not performance, so it's removed before comparing to the prior sub-period's ending value.
  • TWR is independent of cash-flow timing and size by design — the same manager performance produces the same TWR no matter when or how much the client contributed or withdrew.
  • GIPS requires TWR specifically when the client (not the fund) controls cash-flow timing — the standard method for open-ended, liquid structures being compared against a benchmark.
  • When the fund itself controls timing instead — a closed-end or illiquid structure — that's the opposite case, and it's what Money-Weighted Return (next chapter) is built for.
