Modified Dietz

Money-Weighted Return traded Time-Weighted Return's need for interim valuations for something else entirely — an iterative solve with no closed-form answer. Modified Dietz asks whether there's a middle path: something as simple to feed as Money-Weighted Return's plain inputs (a start value, an end value, and the dates and amounts of whatever moved in between), but aimed at Time-Weighted Return's question instead — what did the portfolio itself actually do, independent of when the client's money arrived?

The method takes its name from Peter O. Dietz, who worked the problem in a 1966 study on measuring pension-fund performance, later formalized into industry guidance by the Bank Administration Institute. His motivation was practical, not philosophical: on 1960s computers, an iterative solve like the one behind irrReturn() simply wasn't affordable to run at scale, so Dietz needed something solvable in one direct pass. His first version — now called the Simple Dietz method — assumed every cash flow landed at the exact midpoint of the period: fine when flows are small and evenly spread, misleading when they're not. “Modified” fixes exactly that, weighting each flow by how long it was actually invested for instead. For decades, GIPS treated the result as an acceptable stand-in for true Time-Weighted Return — precisely because it was so cheap to compute.

Run the Time-Weighted Return chapter's own portfolio through modifiedDietz() and the difference shows up immediately: $100,000 → $90,000 → $149,000 (with the $50,000 contribution) → $134,100 chains to Time-Weighted Return's −10.90%, but comes out to −13.61% under Modified Dietz — a real, three-point gap on the exact same numbers. The reason is what each formula is even allowed to look at. Time-Weighted Return uses every valuation point to build a clean sub-period boundary — including the April 1 checkpoint that shows the portfolio had already dropped 10% before the contribution landed. modifiedDietz() never looks at that value at all: for the entries in between the first and last, only their date and cash flow feed the formula, never their value. It weights the $50,000 contribution by how many of the 273 total days it was actually invested for — 92 of them, a 33.70% weight — and blends that into one formula run against just the start and end balances. It's a genuinely coarser lens: no interim valuations required, no iteration, but also no visibility into a decline that happened and then reversed before a cash flow arrived.

Modified Dietz only cares about two things for each cash flow: its date and its amount. The weight below is how many of the period's total days that flow was actually invested for, divided by the total — a flow near the start counts almost fully; one right before the end barely counts at all. Unlike Time-Weighted Return, Modified Dietz never looks at the portfolio's value in between — only where cash moved, and the two endpoint values.

Modified Dietz

  • modifiedDietz(entries) estimates a return from a start value, an end value and dated cash flows in between — weighting each cash flow by the fraction of the period it was actually invested for, rather than assuming a flow's timing the way the original Simple Dietz method did.
  • Unlike timeWeightedReturn(), Modified Dietz never inspects an interior entry's value — only its date and cash flow matter for every entry between the first (opening balance) and the last (ending balance).
  • With no cash flow at all, Modified Dietz reduces exactly to simpleReturn() — the same identity timeWeightedReturn() and unitValueReturn() also satisfy when nothing moves during the period.
  • For decades, GIPS treated Modified Dietz as an acceptable stand-in for true Time-Weighted Return when daily valuation wasn't practical; later revisions moved the standard toward requiring actual time-weighted calculation instead.
  • No iteration and no numerical solve to run to convergence like irrReturn() — Modified Dietz is a single, direct formula, which is exactly the tradeoff that made it attractive before computers could brute-force IRR cheaply.
