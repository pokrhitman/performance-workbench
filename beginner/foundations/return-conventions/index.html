Return Conventions: Percent, Basis Points, Log Returns

Every chapter so far has treated “the return” as a single number waiting to be found — simple, geometric, annualized, but always one figure. There's one more layer most people never notice: even once you've settled on which number is right, there's more than one way to write it down. Percent, basis points and log (arithmic) return aren't three competing calculations the way Time-Weighted and Money-Weighted Return will turn out to be — they're three notations and only one of them is actually a different number from the other two.

Percent needs no introduction at this point — every calculator on this site has output one. Basis points (bps) are just percent zoomed in: 1 basis point is one-hundreth of a percentage point, so 1% = 100 bps and 0.01% = 1 bp. The whole point is precision where a whole percentage point is too coarse to be useful — a management fee moving from 0.75% to 0.80% is a 5-basis-point increase, phrased that way specifically so nobody confuses “5 basis points” with “5 percent.” It's the standard unit for fee comparisons and rate spreads and it'll come back by name once this workbench reaches Advanced tier's cost-layering chapter.

Log return is the one place a genuinely different number shows up. logReturn(beginValue, endValue) computes the natural log of the growth factor — ln(endValue ÷ beginValue) — instead of the growth factor minus one. A portfolio going from $100,000 to $102,000 has a simple return of exactly 2.00%; its log return is 1.98%. Close, but not the same number, and the gap isn't a rounding artifact — it's the mathematical signature of continous compounding and it only grows from here.

Here's what that different number buys you. Compounding and Geometric Linking proved period returns don't add: those three quarters — +10%, −10%, +5% — naively sum to +5.00% simple return, but the actual linked answer is 3.95%. Convert each quarter to a log return first, though — ln(1.10) = 9.53%, ln(0.90) = −10.54%, ln(1.05) = 4.88% — and summing those three numbers gives +3.87%. That's not a coincidence or a different wrong answer: +3.87% is exactly the log return of the true, correctly-linked +3.95% (ln(1.0395) = 3.87%, an exact match, not an approximation — ln(a) + ln(b) + ln(c) = ln(abc) is an identity). Log return are additive across time. It's the one representation on this entire site where naive addition is the right operation, not the wrong one — as long as every period stays in log-return form until the very end and you convert back to simple/percent only once, at the finish.

One more property worth knowing before trying it yourself: log return is always less than or equal to simple return, equal only at exactly 0%. That's not specific to this example — ln(1+x) ≤ x holds for every x above −100%, a direct consequence of compounding being concave rather than linear. Near zero the two numbers are cloe enought not to matter; move to a 50% gain and simple return reads +50.00% while log return reads +40.55%, a 9-point-plus gap that keeps widening the further you get from flat. The Interactive tab plots that exact relationship live — type your own start and end value and watch where your number lands on the curve. That closes out the Beginner tier. From there, this workbench moves into concepts you can't fully reason about from a start value and an end value alone: the next chapter, Time-Weighed-Return, is the first place a cash flow landing partway through the period actually changes how the math has to work.

  • Percent and basis points are the same number in different units — 1% = 100 bps, 0.01% = 1 bp. toBasisPoints() is a pure unit conversion, not a distinct calculation.
  • logReturn(beginValue, endValue) computes ln(endValue ÷ beginValue) — the natural log of the growth factor, not the growth factor minus one. Requires both values strictly positive; unlike simpleReturn(), it has no absolute-value trick for a negative starting balance.
  • Log return is always less than or equal to simple return, equal only at exactly 0% — a direct consequence of ln(1+x) ≤ x. The gap widens with the size of the move, in either direction.
  • Log returns are additive across time: sum the log returns of consecutive periods and you get the log return of the combined period, exactly. It's the one place on this site where naive addition is the correct operation instead of the wrong one.
  • Basis points are the standard precision unit for fees, spreads and rate changes — expect to see them again once this workbench reaches gross-vs-net cost layering in the Advanced tier.
